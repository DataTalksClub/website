{% comment %} The sign-in gate (`_docs/design/specs/signed-in-home.md` §8.3). Registration is account-owned: `_docs/specs/open-decisions.md` §6 and `_docs/specs/04-courses-and-cohorts.md` already rule that it "never creates an anonymous CourseRegistration". The account is not an extra cost but a moved one — homework, the leaderboard and the certificate all need it anyway — so the twenty seconds are spent at the moment of highest motivation, and the registration comes back linked to a person. Only the form is gated. The campaign's marketing copy, video and already-registered count above stay fully visible to an anonymous visitor. The round trip is the existing `?next=` primitive: `safe_next_path` (accounts/navigation.py) honours a local next and only forces "/" for account-transition paths, so signing up or in returns here, where §8.2's short final step is waiting. The signup URL is resolved into a variable and guarded, the way the shared masthead already resolves it, so a deployment without the optional signup route renders the sign-in half instead of failing (issue #296's class of failure). Which way in is offered comes from `accounts.account_entry` (the `account_entry` context variable): the signup form only while it is open; with it closed (production) the configured Google/GitHub/Slack buttons, whose first sign-in creates the account; with neither, an honest notice and the site's contact address instead of a link to a closed page. {% endcomment %} {% comment %} Drawn as the featured slab -- the same card the family landing uses for the cohort to join -- because it is the page's one action for a signed-out visitor. `registration-panel` stays on it as the gate's stable hook. {% endcomment %}
