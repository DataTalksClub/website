{% load custom_filters %} {% comment %} Adversarial redesign (issue #237, `_docs/design/adversarial-redesign-process.md`), implemented against `.tmp/fable-homework-form-mockup.html` and `.tmp/fable-homework-form-design-notes.md`. Field names, ids, POST keys and every `courses.views.homework_*` decision are unchanged -- this is a presentation and client-side-validation pass, not a scoring change. `.work-surface` breaks the 46rem reading column out to a two-column layout from 62rem (see `homework.html`'s own styles): the form keeps its measure, and a sticky rail beside it carries the answered count, the shared progress bar, and a jump-map of numbered discs -- so a 3,500px form says where the student stands without scrolling to the bottom. Below 62rem the rail is replaced by the `.save-bar` sticky footer inside the form. Both read the same per-question "answered" state the `is_question_answered` filter computes for the initial render; `homework_progress.js` keeps it live as the student fills the form in, before anything is saved. {% endcomment %}
