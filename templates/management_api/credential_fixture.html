{% extends "studio/base.html" %} {% comment %} Design 5a (issue #179). The deterministic credential fixture renders on the Studio shell, so it uses the base's admin vocabulary: .admin-section slabs, the shared .field primitives for the create form, .admin-code for the one-time secret and the dashed .row-list for the credential records. The rows keep data-credential-id, which is the hook the browser suite locates a credential by, and every id the copy script binds to (one-time-token, copy-token, copy-status, copy-error) is unchanged, as are the posted action values, idempotency keys and expected revisions. This template is listed in ACCESSIBILITY_AUTHORED_TEMPLATES, so it also keeps the readability shape: one opening tag per line and every Django structural tag alone on its own line. {% endcomment %} {% block title %} Credential lifecycle fixture · Studio {% endblock %} {% block page_head %}
