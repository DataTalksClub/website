{% comment %} The shared paginator, on the design system (issue #179). Eight pages across three families include this partial — the project lists, the Studio Courses tables and the campaign registrations — and every one of them now carries the design system stylesheet, which defines no Tailwind utility and no `app-*` class. The row is therefore built from the shared primitives only, so it needs no rule of its own on any of the eight pages: the numbers are `.filter-pill`s, which is the system's own "one row of controls where exactly one is current" shape, and the current page is marked with `aria-current="page"`, the state the primitive already fills ink for. A direction that leads nowhere keeps the span it has always been, drawn as the quiet bare `.status-pill` so it reads as a marker rather than a control, and the elided range keeps its ellipsis in the same quiet marker. Nothing about the paginator's behaviour moves: the same `?page=` links, the same `pagination_querystring` carried through, the same `aria-label`s on the two directions and the same accessible name on the nav itself. Issue #178 gave the design system one `.pagination` component so that these eight authenticated pages and the public catalogues are one control to look at. This row wears it: the same space above the row, the numbers as the shared `.pagination-number` — the lopsided hand-drawn circle the step discs and the play disc use — the two directions as the stadium `.pagination-step` carrying the arrow rather than the word, and the same quiet marker for a range. Each direction keeps the accessible name it has always had, and the arrow is hidden from assistive technology, so nothing a screen reader hears changes.
