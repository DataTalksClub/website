{% comment %} The account entrance family, design 5a. Sign up, the closed sign-up state, the password reset request, its "check your email" and "your password is changed" outcomes, the reset form itself and the inactive-account notice are one page in seven states: a warm hero carrying the heading, then the content ground carrying the decision. They share these rules, so the rules live here once and each page includes them inside its own single style element, straight after "core/_design_system.html". The system's rule is one inline stylesheet and no external CSS per page — an include inside that style element is how the design system itself is carried, so a family of pages may share a block the same way rather than keeping seven copies that drift. Nothing here is a site-wide primitive: everything below is either an entrance-page layout or the design system's own field treatment attached to the allauth widgets, which render with no class of their own. {% endcomment %} /* The hero holds one heading and one sentence, so its title sits a step under the index-page h1 rather than at hero size. */ .entrance-shell { max-width: 30rem; } .entrance-hero h1 { font-size: clamp(1.7rem, 3.4vw, 2.5rem); letter-spacing: -0.025em; margin-top: 0.6rem; } .entrance-lede { font-size: clamp(0.95rem, 1.5vw, 1.05rem); margin-top: 0.75rem; max-width: var(--measure); } .entrance-alternative { color: var(--body-text); font-size: 0.92rem; margin-top: 0.75rem; } /* The decision panel follows the sign-in card's shared `.card` type scale and spacing, so the two account forms read as one entrance flow. */ .entrance-panel { font-size: 0.9rem; gap: 1rem; padding: 1.35rem; } .entrance-panel h2 { font-size: 1.05rem; } .entrance-form { display: grid; gap: 1rem; } /* The allauth signup, reset-request and set-password forms render plain widgets with no class of their own, so the system's `.field-input` treatment is attached to the controls themselves here.
