## Method and limitations

- GitHub issue number, title, labels, and `OPEN`/`CLOSED` state were read live with
  `gh issue view --repo DataTalksClub/website --json number,title,state,labels,body` at the
  GitHub observation time above. The rows are a frozen capture, not a live dashboard.
- Repository evidence paths were checked against the recorded `refs/heads/main` SHA. The
  issue-comment links are the stable read-only/overlap comments called out during grooming:
  [#99 independent read-only/privacy audit](https://github.com/DataTalksClub/website/issues/99#issuecomment-5229036211)
  and [#112 overlap/reconciliation QA](https://github.com/DataTalksClub/website/issues/112#issuecomment-5233145275).
- Dependency cells use `#N OPEN` or `#N CLOSED` for the captured GitHub state. `HUMAN` is
  an explicit owner, legal, privacy, provider, or operational approval gate; it is never
  treated as evidence-complete. “None recorded” means the issue body did not name a direct
  issue prerequisite, not that downstream work is unblocked.
- `evidence-complete` means the referenced evidence exists for this snapshot only. It does
  not mean that an owner decision, legal approval, production activation, issue closure, or
  the Milestone-0 exit gate has been inferred. `partial`, `missing`, and `blocked` retain
  uncertainty or an explicit gate.
- No production, AWS, database, email, GitHub-write, or protected-data operation was made.
  Evidence can age as `main`, issue state, or external comments change; recapture the matrix
  before a release decision. Screenshots and Playwright are not applicable to this
  documentation-only input.

## Incremental boundary

The matrix records the live issue state and evidence boundary at the captured ref. It does
not replace the full inventories, ownership/authorization matrices, privacy approval, ADRs,
traceability report, or drift gate required by [#72](https://github.com/DataTalksClub/website/issues/72).
Open decisions and HUMAN gates remain open even when a recommendation, implementation, or
narrow evidence artifact exists. A future recapture must use a new snapshot SHA and new UTC
timestamps rather than editing this historical observation in place.
